# 4.5.1 内训方案

## 课程名称

**Python + OpenCV 视觉巡线入门：黑线在画面的哪一边？**

申请人：苏筱蕙（Victoria Mitsu）

## 一、选题与定位

本课程围绕一个可以直接观察的问题展开：给程序一张白底黑线的图片，程序能否指出黑线位于画面的左侧、中间或右侧？同学先在电脑上完成图像处理和位置计算，再讨论如何将偏差量交给机器人的运动控制程序。

课程与巡线小车的感知任务有关，但基础环节不依赖摄像头、开发板和电机。这样可以让不同专业的同学先完成相同的实验，也避免把接线、驱动和视觉算法的故障混在一起。视觉巡线可以作为现有传感器巡线课程的补充，而不是替代已有课程。

本次提交的授课 Demo 约 10 分钟，讲解其中的“图像分割、位置偏差与无效检测”部分。完整内训安排为两次课，每次 90 分钟，间隔一周，建议 20 人、每组 2 人。

## 二、对象与课前准备

面向对机器人感兴趣的新成员，不要求学过计算机视觉或控制理论。建议会运行 Python 文件，理解变量、函数、条件判断和列表。对尚无编程基础的同学，课前提供 30 分钟预备练习：修改变量、调用函数、读取输出。

课前两天发放环境安装说明和一个检查程序。学员提交 Python、NumPy、OpenCV 的版本截图，助教据此安排答疑。课堂按“操作员、观察员”分工，两次实践交换角色，避免只有一人操作。

## 三、可检查的学习目标

| 学习目标 | 课堂检查方式 |
|---|---|
| 说明图像坐标的方向、宽高与 ROI 的作用 | 在图上标出 x 轴和选取区域，说明为何先看下方区域 |
| 解释反向二值化如何将黑线变为白色前景 | 给出灰度值与阈值，预测输出为 0 还是 255 |
| 使用轮廓矩计算横向质心与归一化偏差 | 对照程序结果，手算一个 320 像素宽的例子 |
| 区分“居中”与“没有可靠检测结果” | 居中输出接近 0，丢线输出 None，并给出停止建议 |
| 用实验记录说明方案的边界 | 比较正常、丢线、多目标和阴影案例，记录参数与失败原因 |

## 四、内容边界与技术约定

基础场景为固定视角、白色或浅色背景、单条较深的线。摄像头图像不得水平镜像，图像右侧与机器人右侧对应。算法仅估计图像中的横向位置，不推断真实距离、完整路径或车身姿态。

图像采用 OpenCV 默认的 BGR 读取方式。截取下方 40% 作为 ROI，再转灰度并使用 `THRESH_BINARY_INV`。本课程默认阈值 100，强调这是实验参数，不是所有场景通用的值。符合条件的轮廓必须只有一个，面积与宽度也须在约定范围内；空白、多条明显黑线或大面积阴影应返回无效结果。

横向质心 `cx = m10 / m00`，计算前检查 `m00 > 0`。图像宽为 `W` 时，参考中心为 `(W - 1) / 2`，归一化偏差为：

```text
e = (cx - (W - 1) / 2) / (W / 2)
```

`e < 0` 表示线在左侧，`e > 0` 表示线在右侧。`error = None` 表示本帧无法给出可靠偏差，不能用 0 代替。可选讨论中，差速车右转时左轮较快、右轮较慢；实际接入车辆前还需验证镜像、轮序、限速和停止逻辑。

## 五、教学安排

### 第一次课：图像如何变成位置，90 分钟

| 时间 | 内容与活动 | 学员产出 |
|---|---|---|
| 0–10 分钟 | 看左、中、右三张图，先由人判断，再运行基线程序 | 对任务输入与输出的共同理解 |
| 10–25 分钟 | 图像坐标、BGR 与灰度、ROI。学员修改 ROI 起点并观察 | 一张标注 ROI 的图 |
| 25–40 分钟 | 反向二值化。先预测像素输出，再改变阈值 | 两个阈值对应的掩膜 |
| 40–55 分钟 | 前景轮廓、面积筛选与质心。教师只讲本任务所需概念 | 能说明质心与面积的含义 |
| 55–75 分钟 | 双人补全 `cx` 与 `e` 计算，运行左、中、右案例 | 三组带偏差的结果 |
| 75–85 分钟 | 交换图片互测，排查符号、宽高与阈值问题 | 一条具体的调试记录 |
| 85–90 分钟 | 退出卡：解释 `e > 0`，预测丢线时该输出什么 | 个人理解检查 |

### 第二次课：程序什么时候应该拒绝判断，90 分钟

| 时间 | 内容与活动 | 学员产出 |
|---|---|---|
| 0–10 分钟 | 根据退出卡复习最常见的两类错误 | 修正后的解释 |
| 10–25 分钟 | 比较居中、空白、多条线和大面积阴影 | 有效与无效检测的区别 |
| 25–50 分钟 | 每次只改变一个条件：阈值、背景亮度、ROI 或噪声 | 至少四行实验记录 |
| 50–65 分钟 | 讨论无效帧的停止建议。基础组输出方向，进阶组模拟左右轮指令 | 不把 None 当成 0 的程序 |
| 65–80 分钟 | 组间交换案例，复现对方结果并提出一个改进建议 | 同伴复测记录 |
| 80–90 分钟 | 每组两分钟内说明一次失败及依据，整理提交材料 | 可复现的实验小结 |

## 六、软件、设备与经费

基础设备为每组一台电脑，教师电脑与投影仪各一套。软件使用 Python 3.10 或更新版本、NumPy、OpenCV 的 headless 包和任意文本编辑器。示例将掩膜和标注图保存到文件，不依赖 `imshow`，可以在普通图片查看器中检查结果。

仓库提供固定依赖、合成教学图片、生成脚本、完整参考实现、练习文件和自动化测试。现场网络不可用时，提前分发课程压缩包与适合学员系统的依赖安装包。不能及时修复环境的学员先加入已配置完成的小组，保留课后单独复现任务。

| 项目 | 计划数量 | 预算上限 |
|---|---:|---:|
| 自带或借用电脑、投影设备 | 10 台电脑、1 套投影 | 不新增采购 |
| 打印、白纸、黑胶带等采样材料 | 全班共享 | 60 元 |
| 材料补充预留 | 一份 | 40 元 |
| 基础课程合计 | 20 人 | 100 元以内 |

以上为方案预算上限，实施前按实际库存与报价调整。摄像头、开发板和小车不列为基础课必需采购。进阶采样可借用摄像头，也可使用手机拍摄地面黑线照片；不采集人脸等与课程无关的画面。

## 七、实践任务与评价

必交材料包括：可运行代码、一张带 ROI 和质心标记的结果图、至少四个案例的 CSV 记录，以及 150–300 字的小结。CSV 至少包含图片名、阈值、状态、偏差、方向建议与原因分析。

| 评价项 | 分值 | 判断依据 |
|---|---:|---|
| 功能与语义 | 40 | 左中右判断、偏差符号、丢线与多目标处理正确 |
| 过程解释 | 25 | 能解释反向阈值、质心公式和有效检测条件 |
| 记录与复现 | 25 | 参数与文件齐全，同伴能复现结果 |
| 同伴协作 | 10 | 两人交换角色，记录一次有效反馈 |

不以单张图片“看起来识别成功”作为全部评价依据。进阶任务可尝试自适应阈值、颜色筛选或时间连续性，但须用相同案例比较修改前后，不能以新增算法名称代替验证。

## 八、可能问题与处理

| 问题 | 排查顺序与处理 |
|---|---|
| 安装失败或导入异常 | 检查 Python 解释器与虚拟环境是否一致，确认只安装一种 OpenCV 包，再处理系统依赖 |
| 画面与掩膜相反 | 检查黑线场景是否使用反向二值化，打印阈值前后的像素值 |
| 突然出现大面积前景 | 先查看原图与掩膜，排查背景变暗或阈值过高，暂时返回无效结果 |
| 多条线或路口无法判断 | 记录为多候选，基础版停止建议。路径选择留给后续课程 |
| 质心异常或除零 | 检查候选轮廓是否为空、面积筛选与 m00，不用伪造的 0 偏差继续运行 |
| 同学进度差异较大 | 基础组完成五类固定案例，进阶组增加自采图片与失败分析。助教优先处理公共阻塞 |
| 小车方向与预期相反 | 在接入电机前单独验证图像镜像与左右轮定义，架空车轮低速确认，保留停止开关 |

## 九、课后维护与资料传承

将方案、课件、演示代码、练习与样例按目录存放。每次内训后收集环境问题和两份有代表性的失败记录，去除个人信息后再由维护者审核入库。参数或流程修改应在分支中完成，附运行命令和前后结果，由另一位成员复测后合并。依赖升级单独提交，便于定位后续兼容问题。

本次代码测试使用教学合成图片，验证算法逻辑与输入边界，尚未完成摄像头或实车验证。实施前，教师须用实际教室光照与拍摄视角补充试教，调整参数，确认所需软件可以离线运行。
